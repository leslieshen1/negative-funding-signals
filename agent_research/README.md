# 负费率选币 agent（研究版，独立于冻结 v3）

这是一个对照研究，不改动本仓库冻结的 v3 模型、特征或任何发布文件，也不进入 `RELEASE_MANIFEST.json`。

## 做什么

负费率策略要提前 3 天借好币。这个 agent 负责决定借哪些币。

每个决策日，比如某个周一 00:00 UTC，一个大模型像研究员一样自己查数据、分析，最后交出一张 40 个币的名单，每个带命中概率、类型和理由。名单上的币借到 3 天后能卖，覆盖接下来的一周。

- **命中**：这一周里任何一次已结算费率低于 −0.10%/8h。
- **深度**：费率低于 −0.10% 的程度和时长的累计。

## 能用的工具

agent 不直接上网或连交易所。它通过 8 个工具查数据，工具读的是事先从币安、Bybit、Hyperliquid、CMC 下载整理好的公开数据。每次查询都由程序限制在决策时点之前，agent 看不到未来。查什么、怎么筛、细看哪些币，由 agent 自己决定。

| 工具 | 内容 |
|---|---|
| `market_screen` | 全市场截面，可以按任意字段筛选和排序：<br>• 费率：结算值、预测值、7 天和 30 天均值、最深值<br>• 深负历史：过去 90 天深负天数、距上次深负的天数<br>• 溢价：永续相对现货<br>• 价格：涨跌、相对 30 天高点的回撤<br>• OI：数值及变化、OI 占市值<br>• 成交：永续和现货成交额及两者之比<br>• 其他：市值、流通量变化、Bybit 和 Hyperliquid 的费率、上线天数 |
| `coin_detail` | 单个币最多 120 天的逐日数据，加上它过去每一段深负费率的起止、天数和深度 |
| `coin_hourly` | 小时级走势：费率、预测费率、溢价、价格、OI、成交额。用来看是不是正在转向 |
| `quiet_board` | 全部还没转负的币的总表，保证一个不漏 |
| `announcements` | 币安公告：上新、现货和杠杆的上下架、下架、监控标签、HODLer、Launchpool、费率间隔调整 |
| `base_rates` | 各种情形的历史命中率和平均深度，只用结果已经揭晓的历史 |
| `past_onsets` | 最近"安静币突然转深负"的案例，以及它们当时的样子 |
| `submit_list` | 提交名单 |

目前缺的数据：每个币能借多少、借币利率、解锁日历、盘口深度。

## 效果

对比对象是**已负优先规则**（代码和成绩单里叫 `chronic_rule`）：先放已经在负的币，按 7 天均值排；名额没满，再按过去 90 天深负天数补齐。

评测用的模型是 gpt-6-astra。它的知识截止在 2025 年 10 到 11 月，评测日期都在 2026 年，模型不可能"记得答案"。留出集的规则先写好、代码冻结，只跑了一次。

| | 开发集（2026 年 1 到 6 月，13 次） | 留出集（7 到 10 月，15 周） |
|---|---|---|
| 抓到下周负费率深度：agent | 52.8% | 59.1% |
| 抓到下周负费率深度：已负优先规则 | 50.5% | 55.1% |
| 换成钱（相对"全部币随时可借"）：agent | 48% | 57% |
| 换成钱（相对"全部币随时可借"）：已负优先规则 | 47% | 62% |

- **按负费率深度算，agent 稳定多 2 到 4 个百分点**，但留出集只有 15 周，还不能排除运气。
- **按钱算，两者差不多，留出集上 agent 输了**：主要是漏掉了一个已经在负、仓位能做很大的币（LSK）。agent 看不到每个币能做多大，只看负费率多深。
- **概率比较可信**：说 60% 到 80% 的，实际也差不多。中低档偏乐观。
- **能判断哪些还没转负的币会转负**：命中率是随机挑的 3 倍。判断不了哪个会转得最深，规则和机器学习模型也做不到。

**结论**：现在它大致和简单规则一样好。要明显超过规则，需要补上规则没有的信息，最关键的是每个币能借多少。

## 怎么用

```
python3 data_build.py                         # 从研究缓存生成 agent 用的数据
export LLM_API_KEY=...  LLM_BASE=...          # 任何 OpenAI 兼容、支持工具调用的接口
python3 agent.py 2026-08-17                   # 某一天的 40 个币名单和完整研究记录
python3 eval.py run   --tag 名字 --set dev    # 批量历史评测（dev / holdout）
python3 eval.py score --tag 名字 --set dev    # 和已负优先规则、7 天均值排名、事后完美预测比较
```

每个日期约 2 分钟、约 44 万 token。

还不能直接用于实盘：工具现在读的是历史数据，需要接上实时数据，agent 本身不用改。

## 文件

| 文件 | 作用 |
|---|---|
| `agent.py` | 主循环：调模型 → 执行工具 → 回传结果，直到模型调用 `submit_list`。完整记录写进 `runs/<tag>/<日期>.json`，包括每轮的工具调用、token 用量和代码哈希 |
| `tools.py` | 时点工具层。决策时点由调用方固定，所有查询都在服务端过滤成"决策时点之前" |
| `prompts/system.md` | 整张名单模式（最终版本） |
| `prompts/onset.md` | 只挑"启动"币模式（v2/v3 实验） |
| `eval.py` | 批量运行，以及和基准、完美预测比较打分 |
| `data_build.py` | 从研究缓存生成 `data/`，不进 Git |
| `pnl_backtest.py`、`engine/` | 把每周名单作为借币限制，放进组合引擎算收益 |

| `runs/` | 运行记录和成绩单 |

## 数据

`data_build.py` 需要的研究缓存不在本仓库。它从 `NF_RESEARCH_DIR` 读取：
- `cache2.npz`、`meta2.csv`：330 个币的小时级现货、永续、费率、预测费率、OI，时间范围 2025-04 到 2026-10。
- `data_events/`：公告、CMC 供应量、事件面板。
- `data_xv/`：Bybit 和 Hyperliquid 的费率。
- `cases/episodes_all.csv`：历次深负费率事件。

这些都只用公开行情。

## 评测设计

- **开发集**：2026-01-05 到 06-22，每两周一个日期，共 13 个。用于调整工具和提示词。
- **留出集**：2026-07-06 到 10-12，每周一个日期，共 15 个。按 `PROTOCOL.md` 只跑一次，跑完不改任何东西。
- **对比对象**：
  - 已负优先规则（代码和成绩单里叫 `chronic_rule`）：先放已经负的币，按 7 天均值排；名额没满，再按过去 90 天深负天数和 OI 占市值补齐。
  - 按 7 天均值排名。
  - 事后完美预测。

## 详细结果

### 抓到下周全市场负费率深度的比例（前 40 个币）

| | 开发集 | 留出集 |
|---|---|---|
| **agent（final）** | **52.8%** | **59.1%** |
| 已负优先规则 | 50.5% | 55.1% |
| 7 天均值排名 | 50.7% | 49.0% |
| 事后完美预测 | 98.2% | 100% |

- agent 对已负优先规则：
  - 开发集 +2.3pp，9 赢 2 平 2 输，90% 区间 +0.2 到 +4.3。
  - 留出集 +4.0pp，7 赢 4 平 4 输，区间 −2.2 到 +10.6，不能排除运气。
- agent 对 7 天均值排名：留出集 +10.1pp，区间 +2.6 到 +18.0。
- 概率校准：
  - 高档准：预测 0.59 和 0.77，实际 0.59 和 0.83。
  - 中低档在留出集偏乐观：预测 0.29 和 0.44，实际 0.21 和 0.34。
  - Brier 分数约 0.20。
- 单周的胜负常常由一个币决定，比如 KAITO、ONG（押中），LSK、ERA（漏掉）。

### 换成钱：组合引擎回测，每币等额上限 S/40，本金 1000 万

数字是相对"全部币随时可借"的收益比例。结果文件：`runs/pnl_equal_caps.csv`。

| 名单（improved 退出规则） | 开发集 | 留出集 |
|---|---|---|
| 全部币随时可借 | 100% | 100% |
| **agent** | **48.0%** | **56.6%** |
| 已负优先规则 | 47.0% | 62.3% |
| 7 天均值排名 | 46.5% | 56.1% |
| 事后完美 40 个 | 74.6% | 100% |

- 按钱算，agent 在开发集上和规则持平略高，在留出集上落后。
- 拆开每周的收益：差距主要来自一个币。2026-09-07 那周，规则留着已经在负的 LSK，agent 没选，随后 LSK 价格涨了约 9 倍、费率深负。
- agent 看不到每个币能做多大仓位（容量），它优化的是深度，不是"深度 × 容量"。

### 专门挑"启动"币：v2、v3，开发集，`prompts/onset.md`

下周的负费率深度里，约 43% 来自决策时还没转负的币，而且极度集中：前 5 个占这部分深度的 75%。

| 前 10 名 | 命中率 | 抓到这部分深度的比例 |
|---|---|---|
| agent v2 | 37.7% | 12.8% |
| agent v3（逐页看完全部安静币） | 34.6% | 9.3% |
| 按历史深负天数排序 | 31.5% | 12.4% |
| 随机 | 11.5% | 4.3% |
| 事后完美 | 100% | 91% |

另外，用同样特征训练的 GBM，开发集 18.1%、留出集 8.5%，同期按历史深负天数排序 10.8%。

结论：
- **哪些安静的币会转负，agent 能判断**：命中率是基准的 3 倍。
- **哪个会转得最深，用这些数据谁都判断不了**：agent、规则、机器学习模型都不行。

## 和 v3 模型的关系，以及建议

1. agent 最缺的是容量和到账数量信息，而 v3 的 125 个特征里正好有。把 v3 的概率、经济价值，以及到账数量特征做成 agent 的工具，目标改成"深度 × 容量"，是最直接的下一步。
2. 已经在负、容量又大的币，不应该让 agent 随便丢掉。
3. 2026-07 到 10 已经用作过一次留出集。改进后的版本需要用 2026-10-19 以后、结果已经揭晓的日期来评。

## 成本

整张名单模式下，每个日期平均约 44 万 prompt token，范围 29 到 65 万，耗时约 2 分钟。
